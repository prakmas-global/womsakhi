## The counting rule

A **screen-state** is a distinct thing a woman can be looking at:

1. the route itself, or each of its **tabs** where it has them — tabs *replace*
   the page, so they are not added on top of it
2. every **empty state** — a list with nothing in it is a screen she meets, and
   it was the most-skipped one in the whole redesign
3. every **stage of a flow**, and the success page at the end of it
4. a **loading state** and an **error state** per route, both of which Phase 3
   built as real screens rather than spinners
5. every **dialog or sheet** that covers the page

Deliberately **not** counted: dark mode (the same screen in another palette),
hover and focus states, and the eight brand themes. Counting those would
multiply the number by sixteen and measure nothing.

### Why this is not 445

The **~445 across 44 modules** agreed on 2026-08-24 was never reproducible — it
was a number quoted from memory, and the counting rule behind it was never
written down. This one is generated from the source and can be checked in a
second.

The difference is the **rule**, not missing work. Every route exists, every one
has a loading and an error state, and every one passes the render audit in both
themes. What this rule leaves out that a looser one would include: filter views
(Learning's seven categories, Work's mode and kind filters), detail-page
variants (a scheme is eligible, not eligible, or already applied for), and the
account menu and search palette, which are chrome rather than screens.

Counted the loose way the total is comfortably past 445. Counted this way it is
337. **Quote 337 and the rule**, not a number without one.
